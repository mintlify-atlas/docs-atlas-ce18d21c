This guide walks you through creating and running your first migration using the goose CLI with SQLite — no database server required.

## Prerequisites

Install goose before you start:

```bash
go install github.com/pressly/goose/v3/cmd/goose@latest
```

Verify the installation:

```bash
goose --version
```

<Steps>
  <Step title="Initialize a migrations directory">
    Run `goose init` to create a `migrations/` directory with an initial SQL file:

    ```bash
    goose sqlite3 ./myapp.db init
    ```

    Goose creates the `migrations/` directory and writes a timestamp-prefixed initial file, for example `migrations/20240315120000_initial.sql`. Edit it to add your schema changes.
  </Step>

  <Step title="Create a migration">
    Create a new migration file for adding a users table:

    ```bash
    goose sqlite3 ./myapp.db create add_users_table sql
    ```

    Output:
    ```
    Created new file: migrations/20240315120000_add_users_table.sql
    ```
  </Step>

  <Step title="Write your migration SQL">
    Open the generated file and add your schema changes. Every goose SQL migration requires a `-- +goose Up` annotation, and optionally a `-- +goose Down` for rollbacks:

    ```sql migrations/20240315120000_add_users_table.sql
    -- +goose Up
    CREATE TABLE users (
        id   INTEGER PRIMARY KEY AUTOINCREMENT,
        name TEXT    NOT NULL,
        email TEXT   NOT NULL UNIQUE,
        created_at DATETIME DEFAULT CURRENT_TIMESTAMP
    );

    -- +goose Down
    DROP TABLE users;
    ```
  </Step>

  <Step title="Apply migrations">
    Run all pending migrations:

    ```bash
    goose sqlite3 ./myapp.db up
    ```

    Output:
    ```
    OK   20240315120000_add_users_table.sql (8.34ms)
    goose: successfully migrated database to version: 20240315120000
    ```
  </Step>

  <Step title="Check migration status">
    See which migrations have been applied and which are pending:

    ```bash
    goose sqlite3 ./myapp.db status
    ```

    Output:
    ```
      Applied At                  Migration
      =======================================
      2024/03/15 12:00:00 -- 20240315120000_add_users_table.sql
    ```
  </Step>

  <Step title="Roll back a migration">
    To undo the last applied migration:

    ```bash
    goose sqlite3 ./myapp.db down
    ```

    Output:
    ```
    OK   20240315120000_add_users_table.sql (2.11ms)
    ```
  </Step>
</Steps>

## Use environment variables

Instead of passing the driver and connection string on every command, set them as environment variables:

```bash
export GOOSE_DRIVER=sqlite3
export GOOSE_DBSTRING=./myapp.db

goose status
goose up
goose down
```

Or use a `.env` file — goose loads it automatically:

```env .env
GOOSE_DRIVER=sqlite3
GOOSE_DBSTRING=./myapp.db
GOOSE_MIGRATION_DIR=./migrations
```

<Tip>
  The `-dir` flag (or `GOOSE_MIGRATION_DIR` env var) specifies where goose looks for migration files. The default is the current directory.
</Tip>
